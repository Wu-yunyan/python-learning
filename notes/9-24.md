## ① 账号检查

```bash
cat /etc/passwd
awk -F: '$3==0 {print $1}' /etc/passwd     # 只打印 UID=0 的账号名
grep -v nologin /etc/passwd                # 反选：只剩真能登录的账号
```

`/etc/passwd` 一行 7 个字段，用 `:` 分隔：
`用户名 : 密码占位 : UID : GID : 描述 : 家目录 : 登录 shell`

- **UID 分段**：`0` = root｜`1–999` = 系统账号｜`1000+` = 普通用户
- **第 2 列为什么是 `x`**：密码哈希已移到 `/etc/shadow`（仅 root 可读）。
  早期哈希直接写在 `/etc/passwd` 而该文件全局可读 → 等于密码哈希公开
- **第 7 列 `nologin`**：假 shell，用户一登录就被踢出。给只需跑服务、
  不需真人登录的系统账号用

判断标准：非 root 的 `UID=0` = 后门账号；本该 `nologin` 却挂着 `/bin/bash` = 配置错误

## ② 日志检查

```bash
sudo grep -c "Failed password" /var/log/auth.log
sudo grep "Failed password" /var/log/auth.log | tail -20
sudo grep "Accepted password" /var/log/auth.log
```

**踩到的坑：`grep -c` 返回 1，看起来像被爆破，实际是误报。**

原因：`sudo` 会把自己执行的命令原文写进 `auth.log`，而那条命令行里
就含 `Failed password` 这几个字 → grep 匹配到的是**自己的这次调用**。
可自证：每跑一次计数 +1。

分辨方法——**看第 4 列的"程序名"**

| 程序名 | 含义 |
|---|---|
| `sshd[PID]:` | 真的登录事件 |
| `sudo:` | 提权记账，不是登录 |

正确写法（限定程序名）：

```bash
sudo grep "Failed password" /var/log/auth.log | grep sshd
sudo grep -c "sshd.*Failed password" /var/log/auth.log
sudo journalctl -u ssh --since today | grep "Failed password"
```

结论：**未发现爆破痕迹；工具自身记账产生的 1 条误报已排除。**

## ③ 端口检查

内部视图（靶机内）：

```bash
ss -tunlp
```

外部视图（Windows 侧）：

```bash
nmap -sV 192.168.10.137
```

结果：`999 closed ports` + **仅 `22/tcp open`**（其余服务只监听 `127.0.0.1`，外部不可见）

判断依据：Nmap 靠**对端回应**判断端口状态 ——
回 `SYN-ACK` = open｜回 `RST` = closed｜**无回应 = filtered（被防火墙丢包）**
本次 999 个全是 closed，说明没有防火墙在丢包，主机完全可达。

## ④ 加固闭环：SSH 版本信息泄露

**问题**：banner 泄露精确补丁级别 `Ubuntu 3ubuntu0.17`，可反查 CVE。

| 阶段 | 命令 / 结果 |
|---|---|
| 改前基线 | `nmap -sV -p22 192.168.10.137` → `OpenSSH 8.9p1 Ubuntu 3ubuntu0.17 (Ubuntu Linux; protocol 2.0)` |
| 先查文档 | `man sshd_config \| grep -i -A2 debianbanner`（确认本机版本支持该选项） |
| 整改 | `/etc/ssh/sshd_config` 增加 `DebianBanner no` |
| 生效 | `sudo systemctl reload ssh` |
| 复验 | 同上扫描 → `OpenSSH 8.9p1 (protocol 2.0)`  |

- `reload` 送 SIGHUP 重读配置、不断已有连接；`restart` 会断连接。
  **远程改 SSH 配置必须用 `reload`**，否则会把自己踢下线，配置写错还会彻底锁死
- 改完配置不生效 = 服务仍在用内存里的旧配置，必须 reload / restart

整改结论：精确补丁级别不再对外泄露（低危信息泄露，已整改）。

> 边界认知：banner 能藏，但"22 端口开着"藏不住。加固的真正方向是限制谁
> 能连——`PermitRootLogin no`、`PasswordAuthentication no` 改密钥、限制来源 IP。
