## 二、五条基线核查

在虚机终端跑：

| 命令 | 查什么 | 我这台的输出 |
|---|---|---|
| `sudo awk -F: '($2==""){print $1}' /etc/shadow` | 空口令账号 | 空 |
| `sudo find /etc -perm -o+w -type f 2>/dev/null \| head` | 所有人可写的配置 | 空 |
| `systemctl is-active auditd` | 审计服务 | `inactive` |
| `sudo ufw status verbose` | 主机防火墙 | `状态: 不活动` |
| `ls -l /etc/cron.d/ /etc/cron.daily/` | 可疑定时任务 | 11 个文件，都是软件包自带的 |

## 三、空输出说明什么

`awk` 的写法是「条件成立才 print」。条件是「第 2 个字段为空」，一个空的都没有，它就一行都不打印。**没有输出 = 查完了、没有命中**。

要排除「其实是我敲错了」，就把条件对调再跑一次，让它必然有东西可打印：

```bash
sudo awk -F: '($2!=""){print $1}' /etc/shadow | head -3
```

这次打出 3 个账号名，说明这条命令本身能打印，前面那次是真没匹配。

`!=` 是不等于。

## 四、命令拆解

**`sudo awk -F: '($2==""){print $1}' /etc/shadow`**

- `sudo`：`/etc/shadow` 只有 root 能读
- `awk`：按行读文本、按字段处理
- `-F:`：分隔符是冒号。`/etc/shadow` 每行是 `用户名:密码:...`，所以第 1 段是用户名、第 2 段是密码哈希
- `'($2==""){print $1}'`：第 2 段为空就打印第 1 段

空口令账号等于任何人 `su 用户名` 直接进。

**`sudo find /etc -perm -o+w -type f 2>/dev/null | head`**

- `-perm -o+w`：权限位里「其他人(o)」带「写(w)」，前面的 `-` 表示至少包含这一项
- `-type f`：只要普通文件
- `2>/dev/null`：把报错丢掉。遍历时没权限的目录会把屏幕刷满

配置能被所有人改，谁都能往里塞一条 `PermitRootLogin yes`。

**查文件是谁装的**

```bash
dpkg -S /etc/cron.d/php
cat /etc/cron.d/php
```

输出 `php-common: /etc/cron.d/php`，内容是 `sessionclean` 那一行，PHP 定时清理过期会话用的。

## 五、两个坑

- `/etc/cron.daily/` 里的文件都没有 `.sh` 后缀却带 x 权限：`cron` 的 `run-parts` 不认后缀，只要文件可执行就会跑。排查时不能只盯 `.sh`
- 那些文件时间戳写着 `10月 10 2021`，是打包日期，不代表这台机器那时就在跑这个任务

## 六、ATT&CK 前五个战术

14 个战术里先记最前面 5 个，对照我自己复现时做过的动作：

| 战术 | 中文 | 我做过对应的动作 |
|---|---|---|
| Initial Access | 初始访问 | 把 `shell.php` 传上服务器 |
| Execution | 执行 | `?cmd=id` 让 PHP 跑系统命令 |
| Discovery | 发现 | `id` / `whoami` / `ls -l` / `cat /etc/passwd` |
| Credential Access | 凭据访问 | 没做过。下一步是读 `config.inc.php` 拿数据库账号密码 |
| Exfiltration | 外传 | SQL 注入拖库 |

拿到一台失陷主机，按这条链倒着查：先看外传（异常出站），再看凭据（谁读过配置），再看发现（谁敲过 `whoami`）。

## 七、本机的结论

按五类逐条对下来，「安全审计」和「边界防护」两项不符：`auditd` 没运行、`ufw` 没启用。

其余三项没发现问题：没有空口令账号，`/etc` 权限没有放开，`/etc/cron.d` 里的任务都能对上所属软件包。
