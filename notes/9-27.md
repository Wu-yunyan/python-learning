# 9.27 XSS 反射型 + 存储型

## 反射型 XSS

`vulnerabilities/xss_r/`，Name 框输入：

```
<script>alert(1)</script>
```

弹窗。提交后地址栏变成：

```
.../xss_r/?name=%3Cscript%3Ealert%281%29%3C%2Fscript%3E
```

payload 就挂在 URL 里 —— 服务端收到什么、当场原样吐回什么，不落库，所以叫反射型。
把 `alert(1)` 改成 `alert(2)` 再打一次还是弹，说明弹窗是跟着我的输入走的，不是页面本来就有的。

地址栏里 `%3C` 是 `<`、`%3E` 是 `>`、`%2F` 是 `/`。

源码 `xss_r/source/low.php`：

```php
header ("X-XSS-Protection: 0");

if( array_key_exists( "name", $_GET ) && $_GET[ 'name' ] != NULL ) {
    $html .= '<pre>Hello ' . $_GET[ 'name' ] . '</pre>';
}
```

第一行是响应头，作用是让浏览器不要用它自带的 XSS 过滤（新版 Chrome 已经取消这个功能了，DVWA 留着是为了保证漏洞演示得出来）。
第二行 `$_GET['name']` 从取值到拼进 HTML，中间没有任何处理。

## access.log 每一行是 8 段

```
192.168.10.1 - - [27/Sep/2026:15:15:47 +0800] "GET /DVWA-master/vulnerabilities/xss_r/?name=%3Cscript%3E... HTTP/1.1" 200 1853 "http://192.168.10.137/DVWA-master/vulnerabilities/xss_r/" "Mozilla/5.0 ... Edg/154"
```

来源 IP / 两个 `-` 占位 / 时间 / 请求行（方法 路径+参数 协议）/ 状态码 / 返回字节数 / Referer（这次请求从哪个页面点过来的）/ User-Agent。

来源 IP 全是 `192.168.10.1`。虚机是 NAT 模式，所有从外面进来的请求在虚机眼里都是这一个地址 —— 我的浏览器和 curl 都一样，所以靠 IP 分不出人，只能看 User-Agent（浏览器 UA 里有 `Edg/`）。

日志里有一条我打错参数的：`?id=1%27+OR+%271%27%3D%271`。`xss_r` 只认 `name`，服务端当它不存在，页面照常返回 200 —— 参数名不对，漏洞点就不触发。

## xss_r 三档对比

| 档位 | 做了什么 | 结果 |
|---|---|---|
| low | 无 | 弹窗 |
| medium | 把 `<script>` 删掉 | `<img src=x onerror=alert(1)>` 照样弹 |
| high | 清掉标签 | 同样被 `<img src=x onerror=alert(1)>` 绕过 |

删标签这种黑名单挡不住，换个写法就过去了。

## cookie 与 HttpOnly

low 档把 payload 换成 `<script>alert(document.cookie)</script>`，弹出：

```
PHPSESSID=roih3h21kj6f24l2lvhcclevor; security=low
```

F12 → Application → Cookies，看这两行的 HttpOnly 列：没勾。
手动勾上之后再打一次，`document.cookie` 读不到 PHPSESSID 了 —— 浏览器确实按这个规则来。

服务器侧（虚机外面用 curl 打的响应头）：

| 提交的档位 | Set-Cookie |
|---|---|
| low | `PHPSESSID=...; path=/`（没有 HttpOnly，也没有 SameSite） |
| impossible | `PHPSESSID=...; HttpOnly; SameSite=Strict` |

HttpOnly 是服务器根据档位决定发不发的，不是浏览器的事。

`security.php` 也有 CSRF token，不带 token 的 POST 不生效，响应里一个 Set-Cookie 都没有（我一开始以为服务器不下发，是这里搞错了）。

## 存储型 XSS

`vulnerabilities/xss_s/`，payload 写 Message 框（Name 框 low 档有 `maxlength="10"`，塞不下）：

```
<script>alert(1)</script>
```

提交弹窗；**刷新还弹**；地址栏是干净的 `.../xss_s/`。跟反射型的区别就在这 —— 反射型要 URL 里带 payload 才弹，存储型打开这个页面就弹。

数据库里查得到：

```bash
mysql -u dvwa -pp@ssw0rd dvwa -e "SELECT * FROM guestbook;"
```

## 存储型的源码跟前面不一样

`xss_s/source/low.php`：

```php
$message = trim( $_POST[ 'mtxMessage' ] );
$message = stripslashes( $message );
$message = mysqli_real_escape_string($GLOBALS["___mysqli_ston"], $message);

$query  = "INSERT INTO guestbook ( comment, name ) VALUES ( '$message', '$name' );";
```

它做了转义。`mysqli_real_escape_string` 给单引号加反斜杠，让单引号逃不出字符串。实测：从外面 POST `txtName=wyy'`，服务器没有任何 SQL 报错，页面正常显示 `Name: wyy'` —— 转义在 SQL 这边是有效的。

但这个函数只处理 `'` `"` `\`，不处理 `<` 和 `>`。在数据库看来尖括号没有任何特殊含义，不危险，所以它不需要管。

问题出在显示这一步。抓页面 HTML 原文：

```html
<div id="guestbook_comments">Name: ah<br />Message: <script>alert(document.cookie)</script><br /></div>
```

存进去什么样，显示出来就什么样，`<script>` 一个字符没动。

同一份输入去了两个地方：存进数据库那一步被防住了，显示到网页那一步没有。

## 三份 low.php 摆一起看

| 文件 | 输入去哪 | 结果 |
|---|---|---|
| sqli/low.php | 只进 SQL | 没做处理，SQL 注入成立 |
| xss_r/low.php | 只进 HTML | 没做处理，XSS 成立 |
| xss_s/low.php | 同时进 SQL 和 HTML | SQL 那边转义了，HTML 那边没管 |
