# 2026-09-23 · DVWA 靶场环境准备

## 目标
搭一套本地 Web 漏洞靶场，练习 SQL 注入 / XSS / 文件上传。
选本地虚拟机而不是在线靶场的原因：能自己控制 PHP / 数据库版本、能看服务端日志、
能完整走一遍「漏洞 → 修复 → 验证修复」的闭环，在线靶场做不到最后一步。

## 环境清单
| 组件 | 配置 | 用途 |
|---|---|---|
| VMware Workstation | 17 Pro | 虚拟化平台 |
| Ubuntu | 18.04 Desktop，4C / 4G，NAT | 靶场宿主 |
| Nmap | 7.70 | 端口与服务探测 |
| DVWA | master 源码 | 漏洞练习靶场 |

## 两个环境决策

**1. 网络用 NAT 而不是桥接**
宿主机 VMnet8 网段为 `192.168.10.0/24`，虚机落在 `192.168.10.x`。
这样可以用 Windows 侧的 Nmap 扫虚机，`-sV` 拿到的服务指纹和扫真实内网资产是一样的，
比扫 `127.0.0.1` 有意义——本地回环扫不出防火墙策略、也练不到跨网段探测。

**2. 数据库选 MariaDB 而不是 MySQL**
DVWA 官方 README 明确说明：新版 MySQL 与 PHP 的默认认证配置不兼容，推荐使用 MariaDB。
这条提前查过文档，避免了按 MySQL 装再返工。

## 注意点（记录备查）
DVWA 的 `config.inc.php.dist` 中默认安全等级是 `impossible`，
不手动切到 `low` 的话，漏洞页面不会产生可利用结果——排查时容易误判为"注入失败"。
