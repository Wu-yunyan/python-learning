# 9.26 DVWA 部署 + SQL 注入

## 环境

虚拟机 Ubuntu 22.04，Apache 2.4.52 + PHP 8.1 + MariaDB 10.6.23 + DVWA。

访问路径：浏览器 → Apache → PHP → MariaDB → 回显页面。

数据库按 DVWA 官网 README 用 MariaDB（上面写新版 MySQL 跟 PHP 默认认证对不上）。

## 安装

~~~bash
# 装依赖
sudo apt install -y apache2 mariadb-server mariadb-client php php-mysqli php-gd libapache2-mod-php
sudo systemctl enable --now apache2 mariadb    # enable 才会开机自启，start 只管本次
~~~

装到一半我重启了机器，之后 apt 全报错。补完没配好的包才好：

~~~bash
sudo dpkg --configure -a
sudo apt install -f
~~~

Windows 上传源码到虚拟机（在 Windows 的 PowerShell 里敲）：

~~~bash
scp dvwa.zip wyy@192.168.10.137:/tmp/dvwa.zip
md5sum /tmp/dvwa.zip    # 5144ad1f4481e49a5f9c82a92191275e，1,061,798 字节，跟源文件一致
~~~

第一次连问指纹，输 `yes`。

~~~bash
sudo unzip /tmp/dvwa.zip -d /var/www/html/
cd /var/www/html/DVWA-master
sudo cp config/config.inc.php.dist config/config.inc.php   # .dist 是模板，要复制成正式配置才被读
sudo chown -R www-data:www-data .                          # Apache 用 www-data 跑
sudo chmod -R 755 .
~~~

建了 dvwa 账号，只给它 dvwa 库的权限。浏览器进 `setup.php` 建库，`login.php` 登录，左边 DVWA Security 调难度。

## SQL 注入

User ID 框里输入：

| 输入 | 出来什么 |
|---|---|
| `1` | admin 一条 |
| `1' OR '1'='1` | 全部 5 个用户 |

源码 `vulnerabilities/sqli/source/low.php`：

~~~php
$id = $_REQUEST['id'];                                                     // 客户端传什么就是什么
$query = "SELECT first_name, last_name FROM users WHERE user_id = '$id';"; // 直接拼进 SQL
~~~

两行之间什么都没做。拼完变成 `WHERE user_id = '1' OR '1'='1'`，条件恒成立，整张表都出来。返回的 ID 列显示的是我输入的原文。

另外 `case MYSQL:` 和 `case SQLITE:` 两个分支写法一样 —— 跟用哪种数据库无关。

## 日志

`/var/log/apache2/access.log`：

| 参数 | 状态码 | 响应字节 |
|---|---|---|
| `id=1` | 200 | 1811 |
| `id=1%27+OR+%271%27%3D%271` | 200 | 1870 |

单引号是 `%27`，空格是 `+`，等号是 `%3D`。

注入只比正常多 59 字节，我一开始以为会大很多。但同一个 payload 每次长度都不变 —— 靠这个长度差能判断注入成没成，盲注也是这个路子。
